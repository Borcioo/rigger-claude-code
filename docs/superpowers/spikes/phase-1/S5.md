# S5: what `SubagentStart` input carries, and whether 4 subagent parts arrive

## Question

Which keys does a `SubagentStart` hook read on stdin (`session_id`, `agent_type`, `cwd`,
`hook_event_name`, others), is its `session_id` the parent session's, and do four `SubagentStart`
handlers of one group, each printing JSON `additionalContext` of about 8,800 bytes, all reach the
subagent's first request whole?

## CLI

- `claude --version`: `2.1.327 (Claude Code)`
- `command -v claude`: `<home>/.local/bin/claude.exe` (Windows 11, Git Bash `sh.exe` runs the hooks)
- Read once before S3's first run, in the parent shell; this spike's debug log reports
  `cc_version=2.1.327`, so the CLI did not move.

## Setup

Isolation as in S3: fresh `CLAUDE_CONFIG_DIR` and fake `HOME`/`USERPROFILE`, child env without
`CLAUDE_*`, `ANTHROPIC_*`, `HARNESS_*`, `RIGGER_*`, Remote Control off, `--plugin-dir` run with
`CLAUDE_CODE_PLUGIN_CACHE_DIR` and `HARNESS_LESSONS_INBOX` in scratch and
`HARNESS_LESSONS_BATCH_OFF=1`; the same harness passed the S3 canary earlier in the same session.
Scratch: `<temp>/rigger-p1/S5/run1`.

- **Stub** (the plan's `stub_tool.py`, kept as a reply function inside `s5.py` on top of the
  shared `harness.py` copy of `stub_api.py`): to the request carrying
  the probe word `s5probe-<uuid>` with no `tool_result` yet, it answers with a `tool_use` of the
  tool named `Agent` (the name read from the request's `tools` list), input
  `{"description": "s5 probe", "prompt": "s5sub-<uuid>", "subagent_type": "general-purpose"}`;
  every other request gets a text reply.
- **Scratch plugin** `spike-s5`: a `SessionStart` (matcher `startup`) handler and a first
  `SubagentStart` handler each run `cat > "$S5_OUT/in-<event>-$$.json"`. Four more `SubagentStart`
  handlers in the same group each `cat` a prepared file holding
  `{"hookSpecificOutput": {"hookEventName": "SubagentStart", "additionalContext": …}}`, whose text
  is `S5-SUB-<run>-<i>`, filler lines up to 8,800 bytes and a last line `S5-END-<run>-<i>`
  (8,841 bytes of text each).
- **Run:** `claude -p s5probe-<uuid> --model haiku --output-format json --allowedTools Agent
  --plugin-dir <temp>/rigger-p1/S5/run1/plugin --debug-file <temp>/rigger-p1/S5/run1/debug.log`.
- The subagent's request is the one whose messages carry `s5sub-<uuid>` and not the probe word.

## Control

The stub received a request carrying `s5sub-<uuid>` without the probe word: 1 such request (4
requests in all), so a subagent ran. The debug log has five
`Hooks: SubagentStart:general-purpose [...] (plugin spike-s5@inline) finished with status 0` lines,
one per handler. Observed: yes.

## Observed

`SessionStart` stdin keys: `cwd`, `hook_event_name`, `session_id`, `source`, `transcript_path`.

`SubagentStart` stdin keys: `agent_id`, `agent_type`, `cwd`, `hook_event_name`, `prompt_id`,
`session_id`, `transcript_path`.

| Item | Value |
|---|---|
| `session_id` in `SubagentStart` = `SessionStart`'s | yes; also equal to the `session_id` of the `-p` result, the parent session |
| `transcript_path` | the parent's transcript (`<config dir>/projects/<cwd slug>/<parent session id>.jsonl`) |
| `cwd` | the parent's cwd |
| `agent_type` | `general-purpose` (the `subagent_type` given to the tool); the debug log's matcher field shows the same string (`SubagentStart:general-purpose`) |
| `agent_id` | a 17-character hex id, different from `session_id` |
| `prompt_id` | a uuid |
| Subagent prompt in stdin | no key carries it |
| `SessionStart` fired for the subagent | no: one `SessionStart` input file in total |

Markers in the subagent's first request:

| Marker | Count |
|---|---|
| `S5-SUB-<run>-1` … `-4` | 1 each |
| `S5-END-<run>-1` … `-4` | 1 each |

No part was cut or persisted to a file, and no `S5-SUB` marker reached the parent's requests.
Handler finish order in the debug log was 1, 2, copy-stdin, 3, 4 (handlers of one group run in
parallel).

## Decision

- **The parent `session_id` arrives** (branch "If the parent `session_id` arrives"): Task 14's
  subagent parts read the parent's snapshot by `session_id` and recompute from files only when it
  is missing.
- **All 4 markers and all 4 end lines arrived** at 8,841 bytes of text per part, so the four
  subagent parts stay as designed; no `BLOCKED`.
