# Q2: what `SubagentStop` carries

## Question

For a subagent's stop, what does a `SubagentStop` hook read on stdin? Specifically:

- Is its `session_id` the parent session's?
- Is the subagent's last reply in the event, whole at 2 KB, 40 KB and 300 KB?
- Does the agent transcript hold the reply too?
- What form does `agent_type` take for a plugin's agent?

## Setup

- **Isolation:** as in Q1. Each run had a fresh config and fake home, a stripped child environment
  that keeps `CLAUDE_CODE_CHILD_SESSION`, and the local stub behind `ANTHROPIC_BASE_URL`. The canary
  passed on both binaries.
- **Live state:** the hash of the live `installed_plugins.json` was the same before and after every
  run.
- **Probe plugin** `spike-q2`:
  - an agent `agents/echo.md` (`name: echo`);
  - a `SubagentStart` handler and a `SubagentStop` handler, each `cat > "$Q2_OUT/<event>-$$.json"`.
- **Stub:**
  - To the request that carries `q2probe-<uuid>` and has no `tool_result`, it answers with an `Agent`
    tool_use: `subagent_type` is the run's type, prompt `q2sub-<uuid>`.
  - To the request that carries `q2sub-<uuid>` without the probe word, it answers with a text of the
    run's size. The text is a first line `STATUS: DONE`, then filler lines, then a last fenced `json`
    block holding `{"marker": "Q2-END-<run>"}`.
- **Run:** `claude -p q2probe-<uuid> --model haiku --output-format json --allowedTools Agent
  --plugin-dir <plugin> --debug-file <log>`. The parent's session id is the `session_id` of the `-p`
  result.
- Scratch: `<temp>/rigger-p2/q/Q2/`.

**Parse time.** The measured step reads the 300 KB `SubagentStop` stdin file (312,594 bytes),
decodes the JSON, finds the last ```` ```json ```` fence with `rfind` and decodes the block. It took
0.89 ms (median of 20, 2.1.327 run) and 0.80 ms (2.1.330 run), against the shadow's 2.5 s bound. At
2 KB it took 0.08 ms. Interpreter start-up is excluded.

## Answer

- `session_id` is the parent's, at every size and for both agent types, on both binaries.
- `last_assistant_message` holds the whole reply and ends with the marker block at 2 KB, 40 KB and
  300 KB. It was not cut at any size measured. The agent transcript holds the same text.
- `agent_type` for a plugin's agent is `<plugin>:<agent>` (`spike-q2:echo`), the same string as the
  `subagent_type` the orchestrator passed.

## Decision

- **`session_id` is the parent's:** Task 17 reads the slot table from that session's snapshot.
- **`last_assistant_message` ends with the marker at every size:** Task 17 checks the event text and
  does not read the transcript tail.
- **`agent_type` for the plugin agent is `spike-q2:echo`:** a slot is found by comparing
  `agent_type` with the slot target, with no mapping.
