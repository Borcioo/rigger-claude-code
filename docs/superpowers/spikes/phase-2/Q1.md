# Q1: does a line repeated after a compaction arrive

## Question

A `SessionStart` handler with the matcher `startup|compact` prints the same text at every firing of
one session. After `/compact`, does that text reach the model again, or does Claude Code drop it as
a copy of the line it printed at startup?

## CLI

Read right before the first run, and again from each run's debug log (`cc_version`):

| Binary | `--version` | Debug log |
|---|---|---|
| PATH CLI, `<home>/.local/bin/claude.exe` (Windows 11, Git Bash `sh.exe` runs the hooks) | `2.1.327 (Claude Code)` | `cc_version=2.1.327.*` |
| The desktop app's copy, `<home>/AppData/Roaming/Claude/claude-code/2.1.330/<build>/claude.exe` | `2.1.330 (Claude Code)` | `cc_version=2.1.330.*` |

Every run below was made once with each binary.

## Setup

- **Isolation:** a fresh `CLAUDE_CONFIG_DIR` and fake `HOME`/`USERPROFILE` per session. The child
  environment drops `CLAUDE_*`, `ANTHROPIC_*`, `HARNESS_*` and `RIGGER_*` and keeps
  `CLAUDE_CODE_CHILD_SESSION`. `ANTHROPIC_BASE_URL` points at a local stub (the pattern of
  `plugins/rigger-rules/tests/stub_api.py`). `CLAUDE_CODE_PLUGIN_CACHE_DIR` and
  `HARNESS_LESSONS_INBOX` point at scratch folders.
- **Canary:** one stub run on a scratch config per binary, before the spike. The probe word reached
  the stub and the scratch config, and no live config file touched during the run held it. Result:
  `CANARY PASS` on both.
- **Live state:** the hash of the live `installed_plugins.json` was recorded before and after every
  run. It did not change in any run.
- **Probe plugin** `spike-q1`: one `SessionStart` group, matcher `startup|compact`, timeout 10 on
  each handler.
  - `same`: `printf 'Q1-SAME-%s\n' "$SPIKE_RUN"`. `SPIKE_RUN` is a fresh id per session, the same
    for all three turns of that session.
  - `firing`: reads `source` from the hook JSON and prints `Q1-FIRING-<source>-<epoch seconds>`.
- **Session:** `claude -p q1probe-<uuid> --session-id <id>`, then `claude -p "/compact" --resume
  <id>`, then `claude -p q1probe-<uuid2> --resume <id>`. Each turn has `--plugin-dir`,
  `--model haiku`, `--output-format json` and its own `--debug-file`.
- **Counting:** marker substrings are counted in the first request whose messages carry the probe
  word. Hook text arrives prefixed, as `SessionStart:<source> hook success: <line>`.
- Scratch: `<temp>/rigger-p2/q/Q1/`.

## Control (Step 2)

The turn-1 request that carries the first probe word:

| Marker | Expected | PATH CLI | Desktop copy |
|---|---|---|---|
| `Q1-SAME-<run>` | 1 | 1 | 1 |
| `Q1-FIRING-startup-…` | 1 | 1 | 1 |
| `Q1-FIRING-compact-…` | 0 | 0 | 0 |

The control passed in all six sessions. The harness counts correctly.

## Observed (Step 3)

This is the request that carries the second probe word, after `/compact`. Three sessions were run
per binary.

| Binary | Session | `Q1-SAME` | `Q1-FIRING-compact` | `Q1-FIRING-startup` | `SessionStart:compact` in the turn-2 debug log | Exit codes |
|---|---|---|---|---|---|---|
| 2.1.327 | 1 | 1 | 1 | 0 | yes | 0, 0, 0 |
| 2.1.327 | 2 | 1 | 1 | 0 | yes | 0, 0, 0 |
| 2.1.327 | 3 | 1 | 1 | 0 | yes | 0, 0, 0 |
| 2.1.330 | 1 | 1 | 1 | 0 | yes | 0, 0, 0 |
| 2.1.330 | 2 | 1 | 1 | 0 | yes | 0, 0, 0 |
| 2.1.330 | 3 | 1 | 1 | 0 | yes | 0, 0, 0 |

The lines as they arrive after the compaction (one session):

```
SessionStart:compact hook success: Q1-FIRING-compact-<epoch>
SessionStart:compact hook success: Q1-SAME-<run>
```

Turn 2's debug log has both handlers as
`Hooks: SessionStart:compact [<command>] (plugin spike-q1@inline) finished with status 0`.

`Q1-FIRING-startup` is gone after the compaction, so the startup copy did not survive it. The stub's
summary is `STUB-REPLY`, so a summary cannot have copied `Q1-SAME`. The one `Q1-SAME` therefore comes
from the `compact` firing. Its text equals the startup line, and it was not deduplicated against it.

## Answer

Yes. A line already printed at startup arrives again after `/compact` when a `compact` handler
prints it, in 3 of 3 sessions on both binaries. Without that handler, the startup copy is gone after
the compaction (`Q1-FIRING-startup` 0).

## Decision

Branch: **`Q1-SAME` arrives after the compaction in all 3.** D31 adds `compact` to the matchers of
the five `core_check.sh` handlers (`startup|clear|compact`). Task 5 changes the five `hooks.json`,
`test_wiring` and `tests/test_repo.py:548`, and times five starts as its Step 4 says.
